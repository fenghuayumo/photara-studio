# SfM 性能分析：Global 与 Hierarchical

分析范围：几百至几千张图片，兼顾运行时间与对齐质量。日期：2026-10-11。

## 实验条件与计时边界

- 数据：`D:/Models/berlin/images/`，1511 张图片；参考模型：`D:/Models/berlin/sparse/0/`。
- 硬件：AMD Ryzen 9 7950X，16 核/32 线程，约 32 GB 内存；RTX 5090 D v2，约 24 GB 显存。
- Release 构建，默认 SiftGPU / gpu_mutual_ratio，27000 特征上限，顺序窗口 3，并补充 BoW 检索。
- Global 首轮使用冷缓存。Hierarchical 对照使用相同前端轨迹缓存；冷启动与缓存启动的总时间不可直接比较。
- 参考模型用于一致性比较，不能直接当成测量真值。相机中心误差先经 Sim(3) 对齐，再除以参考轨迹相邻相机距离的中位数。
- 当前每种配置先做一轮诊断，不能据此声称稳定加速倍数；正式验收应至少重复三次，报告中位数及波动范围。
- Global 的 CLI 在输出 SfM 后因显式 `--capture-mode scene` 自动进入训练，已停止；这里只统计 `sfm.reconstruct` 结束之前的阶段，完全排除训练。
- 一个初始 Python 对照因词典路径参与缓存键而重新匹配，已中止并排除。正式默认 Hierarchical 对照日志已确认 `checkpoint hit: tracks`。

## 默认 Hierarchical 对照（2048 容量）

确认命中 tracks 缓存，前端读取耗时 3.283 s。Hierarchical 核心阶段 82.583 s，其中嵌套 Global 为 81.771 s；完整重建 189.789 s，映射后收尾约 104 s。Global 与默认 Hierarchical 核心阶段处于相近水平，不能把 311.5 s 对 189.8 s 的总耗时差当作算法加速。

结果同为 1508/1511 相机。Hierarchical 重投影均值 0.472428 px、RMS 0.624662 px；参考旋转误差中位数 0.16435°、P95 0.36866°，归一化中心误差中位数 0.01867、P95 0.04619，与首轮 Global 接近。

另一个配置注意点：单子场景调用 `run_global_mapping(global_scene, {}, {}, config.resection)`，没有接收父 `ReconstructionConfig` 的 global_rotation/global_positioning 设置。因此给 Hierarchical 配置 Global 定位后端或轨迹预算不能假定生效；应明确传递这些配置或报告实际 backend，避免优化实验测错路径。

## 代码事实与优化顺序

### 1. 优先减少恢复阶段的全量重复工作

代码：`photara/src/sfm/submap_recovery.cpp` 的 `recover_weakly_connected_views` / `propagate`，以及 `photara/src/sfm/reconstruct.cpp` 的 `finish_alignment_recovery`。

恢复每推进一轮，就重新 `build_tracks(scene)` 并全量 `triangulate_tracks(scene, false, ...)`。本次只恢复少量相机，却反复处理百万级轨迹；完整恢复/收尾比核心映射更耗时。

建议先为恢复阶段增加独立计时，并记录每波恢复相机数、受影响轨迹数、全量扫描数。然后复用原始验证匹配的轨迹拓扑，按新恢复相机涉及的轨迹及拓扑变更闭包重建/三角化。现有 `triangulate_tracks(scene, track_ids, ...)` 和局部过滤接口可作为基础。

边界：不能只取相机直接观测的轨迹；重建、合并和分裂可能改变关联轨迹。仍需排除未通过独立验证的相机深度，保留 held-out 验证、强度门限和失败回退，并在最后执行一次全量检查。不能用降低质量门限或跳过恢复代替优化。

### 2. 优化定位的逐列稠密 Cholesky

代码：`photara/src/ba/bearing_cuda.cu` 的 `CudaBearingOptimizer::solve`；Vulkan 对应 `photara/src/ba/bearing_vulkan.cpp`。

CUDA 当前按系统每一列启动 `chol_pivot<<<1,1>>>` 与 `chol_rank1`。本次 GPU 实际包含 1507 个相机，即 4521 维系统，每次分解约 9041 次 kernel 启动。Vulkan 也采用逐列 dispatch。源码证明存在大量串行列依赖；是否分解占定位的主要时间，还需 GPU 子阶段计时确认。

定位的点约束求解运行 45.6452 s，已用尽默认约 45 s 的预算，仅完成部分 IRLS；这不是已充分收敛的计时。优化后可能首先在同样预算内完成更多求解，而不是立即缩短到相同百分比。

CUDA 可评估已安装 CUDA 12.8 中的 `cusolverDnDpotrf` / `cusolverDnDpotrs`，或分块分解；当前 BA 目标尚未链接 cuSolver，需要补构建与工作区管理。Vulkan 优先考虑分块 Cholesky；更大场景再评估稀疏/矩阵自由 PCG。保留锚点、尺度约束、阻尼和数值失败回退。保持双精度，混合精度属于单独的质量实验。

### 3. 清理 Hierarchical 单子场景的无用副本

代码：`photara/src/sfm/hierarchical.cpp` 的 `split_hierarchical_scene` / `run_hierarchical_mapping`。

默认容量是 2048 张；1511 张 Berlin 确定走单子场景分支，并在其中调用 Global。现在先提取完整子场景，之后才判断只有一个子场景；进入分支后又创建 `Scene global_scene = scene` 以保留失败回退。前一个完整子场景副本在分支中不使用。

建议把聚类规划和子场景提取分开，发现单子场景后直接进入现有 Global 分支，避免先创建未使用的副本。保留 Global 失败时的可靠回退快照；不要把两个副本都简单删除。本项语义风险较低，但默认对照目前显示副本相关时间在秒以内，不能把它当成 Berlin 的主要加速来源。

多子场景提取还逐个扫描全局 pairs/tracks，并复制各自 track，随后每个 worker 又调用 `build_tracks`。可用 image→pairs / image→tracks 索引分发；若删除提取阶段 track 复制，须审计公开 `split_hierarchical_scene` 调用方的契约。

### 4. 分离 BA 打包、可观测性门控、GPU 传输和求解时间

代码：`photara/src/sfm/bundle.cpp`、`photara/src/ba/optimizer_cuda.cu`、`photara/src/ba/optimizer_vulkan.cpp`。

每次 BA 都重新遍历轨迹并构造 Problem、观测邻接和 GPU 资源；Global 分阶段 BA 及恢复 BA 会重复这些工作。CUDA BA 的日志子计时目前为零，不能根据这些零值声称没有组装或求解成本。

建议先补完整端到端 BA 子计时，再缓存未变化的观测拓扑与邻接；只有轨迹、inlier、活动相机和内参组发生变化才失效。内参可观测性门控当前按相机组重复扫描全部轨迹、重复计算轨迹视差，可在同一轮 BA 中一次计算后分发；跨 BA 缓存必须在位姿/点改变后失效。

本次主 BA 中 PCG 经常达到 100 次上限。优先记录最终相对残差和预条件器效果，再比较预条件器/容差策略；达到上限本身不能证明每次迭代都多余。已有 CUDA graph PCG 实现，不能把“改用 CUDA Graph”当成尚未实现的方案。

### 5. 多子场景策略和 Sim(3) 合并

默认 2048 容量的 Berlin 测试不能代表真正的多子场景 Hierarchical。需要在相同 tracks 输入上单独比较容量 512 等设置，并记录实际分簇数、最大/最小簇大小、注册率、合并失败和参考位姿误差。

当前 worker 数按子场景数分配，内部线程预算按 CPU 总线程均分；该机制已存在。优化应测量簇大小和观测量导致的尾部负载，并考虑 GPU 求解串行/并发争用，而不是重新加入已有线程预算。

分簇过程每次合并都会重新扫描图并重建簇间边权与优先队列；可维护簇邻接与版本号，仅更新被合并簇的边，遇到全局局部搜索调整时再全量重建。该项的实际收益需独立分簇计时验证。

Sim(3) RANSAC 固定执行至 2048 次，每轮重新分配内点容器并扫描全部对应点。可复用容器并基于可信内点率自适应停止，保留固定种子和失败回退；这是次要优化，须先测量合并时间，不能从源码直接推断它主导本次耗时。

## 验收与后续实验

- 优先做保持计算语义的改动：精确删除无用副本、减少重复数据打包、复用同一轮的几何统计。
- 恢复阶段和线性求解器改动属于质量敏感优化；同时检查注册图片集合、参考旋转/中心误差 P50/P95、重投影误差、可靠相机数及未注册图片清单。
- 冷启动计时单独列出前端；映射比较必须复用相同 tracks 输入并禁止 reconstruction 缓存捷径。
- 每项改动分别做 A/B，至少 3 次重复；记录 CPU/RAM、GPU 显存及真实 backend，不把一次运行波动当成加速。
- 不以减少特征上限、降低定位轨迹数、减少恢复次数作为第一轮主优化；这些会改变覆盖率和质量，应在后面的独立实验中评估。

实验脚本、原始日志、资源采样、参考比较及汇总 JSON 均位于 `experiments/sfm_perf_berlin_20261011/`。接受的三项诊断实验均已完成；中止的两个进程（额外训练、初始错误缓存对照）不计入有效实验。构建基于 HEAD `60173ffda724d74e50c68601767cff02f3c6a7ad` 加上工作区已移除独立 incremental 模式的修改，本轮没有改变求解器或质量阈值。

## 优化实现（2026-10-11）

本节记录上述诊断之后的实现。基线目录保持不变，新实验位于 `experiments/sfm_opt_berlin_20261011/`。

1. 弱分支恢复在一次恢复调用中缓存原始 verified 轨迹拓扑，后续恢复轮次直接恢复该拓扑。相机位姿和注册状态都未变化、且上次没有剥离 split child 的有效轨迹复用三角化结果；其余轨迹从原始匹配重新求解。发生 pair 清理时执行完整重建；进入后续 BA 前释放缓存。没有减少恢复轮次或放宽独立验证阈值。`WeakBranchRecoveryOptions::reuse_verified_geometry=false` 保留离线完整重建对照路径。
2. CUDA bearing 定位使用 32 列共享内存面板分解、面板求解及 16×16 tile 的 trailing update，保留双精度、SPD 错误检查、阻尼、锚点和尺度约束。4521 维分解由约 9041 次 launch 降为 424 次。未引入 cuSolver 的额外 DLL 链。Vulkan 定位的逐列分解尚未改变。
3. BA 使用连续 image→pose 索引，预留点和观测内存；同一轮中每条轨迹的视差只计算一次并分发到不同内参组，射线只归一化一次。保留现有观测迭代顺序和内参门控条件。增加打包耗时和 CUDA PCG 最终相对残差日志。CUDA 相机预条件器改用点消元后的 Schur 对角块，并对锁定旋转/平移取活动参数的主子块；分解失败保留现有对角回退。内参组预条件器、PCG 容差和迭代上限保持不变。
4. Hierarchical 先规划簇，再提取多子场景；单簇时跳过未使用的完整子场景副本，保留 Global 失败回退所需的场景快照。默认容量仍为 2048。

缓存恢复与完整重建的走廊回归比较位姿、点、内点数、split 轨迹及观测顺序。CUDA bearing 回归覆盖跨越 32/64 列边界的矩阵、单步 Ceres 对照、弱尺度方向及加权 Huber。BA 增加仅旋转和仅平移的 CPU/GPU 单步对照，最大参数差异低于 1e-14。最终构建包含 CLI、编辑器和 Python；7 项相关 CTest 通过。

新旧前端的 features、matches、geometry、tracks 检查点虽然因源码指纹产生不同文件名，但 payload 大小和校验值完全相同。例如 tracks payload 为 461360947 字节、校验 `77cbb50c5d444da7`，确认映射比较使用相同输入。新算法重建缓存使用新的源码指纹；多簇 Python 测试显式禁止写入重建缓存。

初版 `global` / `hierarchical_2048` 尚未采用 Schur 预条件器，只用于记录中间效果。`global_schur` 是发现锁定参数处理问题后中止的实验，不作为有效结果。最终修正版使用带 `schur_mask` 的输出名；不得将中间结果写作最终版本的性能。

### 多簇旋转一致性恢复

新增 `recover_rotation_inconsistent_views`，接在真正多簇 Hierarchical 的合并、BA、轨迹筛选及补注册之后；单簇快速路径不执行额外审查。

- 在独立的轻量验证图上执行全局旋转平均。每条边只编码原 composite weight 和相对姿态，不复制匹配、特征或轨迹，也不修改原始 pair 的 active 状态。
- 将旋转平均结果与当前模型通过共同旋转 gauge 对齐，剔除超过 5° 的候选后重新估计 gauge。仅在至少 80% 的共同注册相机形成一致集合时继续；无主导共识时保持原模型。
- 旋转差异只负责提名候选，不直接覆盖任何姿态。替代姿态必须通过现有 stable-only 多视深度、PnP、独立验证像素、空间分布及相对基线验证。通过验证的相机可成为下一轮锚点，失败的候选保留原几何。

离线原型仅输入相同 tracks 检查点和 `hierarchical_512_schur_mask.asfm`，未读取参考姿态作检测或恢复。它恰好识别六张异常相机，依次恢复 2 / 3 / 1 张；全部接受后才运行参考评估。结果是注册 1511、参考 Sim(3) 共识 1511、最大旋转误差 1.10499°，中心 median / P95 为 0.010742 / 0.032057 steps。该离线结果不是完整流程耗时，不能替代生产重跑。

### 本轮结论与数据边界

默认 Global / H2048 在四套数据上保持高覆盖与有限几何，Playroom 的 CPU / CUDA 对照十分接近。仍不能给出“所有 Hierarchical 分簇配置均已鲁棒”的结论：小容量分簇在室内与全景数据上损失覆盖，且全景审计需改用相机模型对应的全球残差。保留默认容量 2048，后续优先补强弱子场景恢复、合并覆盖检查和全景审计。

测试用的是现有参考重建，来源并非全部可验证的独立真值；办公室没有参考。本轮没有完整更改前版本的四数据集 A/B，因此结果是对当前实现的跨数据验证及后端对照，不是无回归的形式证明。冷 Global 的 39.886 / 168.043 / 255.648 / 124.353 s 包含前端，缓存命中的默认 H 为 13.866 / 76.384 / 51.895 / 68.996 s，二者不能直接拿来计算算法加速倍数。

## 质量修复与再次验证（2026-10-12）

先提交上述性能优化和初轮鲁棒性分析，提交为 `cbd67f6`。随后根据小容量分簇的实际失败补强质量路径，未放宽重投影、三角化角度或最终注册支持阈值：

1. 全景摘要、最终注册支持审计和弱子图恢复改用相机模型对应的 checked residual。球面包含有效后半球，使用接缝 / 极点安全的切平面像素残差，并拒绝反向射线的零残差假极小值。
2. 局部 Star 失败或覆盖不足 98% 时，以原始内参和验证图像对做簇内 Global 重试。候选先通过观测支持审计；有效 Star 仅在候选覆盖更高时被替换。显式 CPU 选择也作用于重试定位。
3. 多簇提取前在父场景保留物理相机 / EXIF 焦段内参分组。室内数据的局部 Global 原本分成 5 组，但合并回共享父相机时被压回 1 组；现在局部内参更新回各自父组。
4. 合并 BA 后重新三角化改变了优化目标，增加有界收尾 BA，复用现有 `final_ba_additional_iterations=60` 预算；设为零可关闭。失败或新增强旋转冲突时恢复此前姿态、内参、轨迹、注册代数及轨迹索引。冲突要求至少两个不同的非平面强邻居，以及足够的三角 / 循环一致性，不能仅凭更小的像素代价接受异常姿态。
5. CUDA PCG 图捕获异常路径显式结束捕获后再销毁流，防止失败捕获状态污染后续同步迭代或其他簇的求解。
6. 收尾 BA 回退仅防止新增冲突；对已存在或后续恢复引入的冲突，在全部恢复结束后再做严格旋转审计。无法通过稳定深度 PnP 可靠修复的严重冲突姿态不计入有效对齐，其观测退出轨迹内点区间。CLI 与 Python 分阶段映射共用 `reconstruct_from_frontend`，执行相同选项、元数据刷新、恢复和最终审计。

保留每个中间版本的模型和日志。`initial_fix/` 为球面审计及局部重试版本，`postdensify/` 为尚未加入内参分组和回退保护的收尾 BA 版本；后者暴露办公室约 12° 的真实旋转回归。最高权重图像对 `video06_00074` / `video06_00079` 有 277 个匹配，其相对旋转误差从 Global 的 0.171° 增至 12.326°；另一个独立强邻居也不支持该姿态，因此增加上述回退保护，而不是复制参考姿态。

本轮依然分别测试 Global、默认 H2048 和真实 H128 / H256。默认四套均走单簇 Global 快速路径，不能用默认结果替代多簇验收。重建缓存禁用，复用同一份前端数据，所有热缓存 preflight 提取 / 匹配 / 轨迹时间均为零。当前运行存在外部 GPU 训练程序，本轮用于质量验证，不作为新的性能加速证据；前文 Berlin 272.360 s 属于 `cbd67f6` 之前验证的实现，不能直接作为新增收尾 BA 后的完整流程耗时。

最后的四套多簇复测通过离线工具 `--hierarchical CLUSTER_CAPACITY` 显式读取原始 `tracks-HEX.bin`，调用上述生产共享映射入口，重新执行局部重建、合并、BA、恢复和全部最终审计。没有读入完成重建的姿态，也没有重命名缓存键或强行制造新版本缓存命中；前端输入在运行前后校验 SHA-256 一致。此阶段不重新提取 / 匹配，也不把映射计时当作冷启动全流程计时。

### 最终结果与验收边界

本轮共完成 25 次生产映射 / 重建（首轮 13 次，三轮多簇复测各 4 次），另外保留 3 次独立全景 BA 探针。最新四套真实多簇结果如下；之前的部分版本虽注册数增加，仍发现严重旋转异常，不能视为质量验收通过。

| 数据集 / 簇容量 | 修复前多簇注册 | 最终多簇注册 | 最终 H RMS (px) | Global RMS (px) |
|---|---:|---:|---:|---:|
| Playroom / 128 | 225 / 225 | 225 / 225 | 0.824612 | 0.619588 |
| 室内iphone / 256 | 703 / 739 | 739 / 739 | 0.958988 | 0.776707 |
| 办公室 / 256 | 894 / 900 | 900 / 900 | 0.887530 | 0.676115 |
| VID 全景 / 128 | 263 / 375 | 375 / 375 | 0.414468 | 0.369115 |

全景使用新的全球切平面像素口径，不能与旧程序前半球摘要直接比较。独立复核最终 844636 个内点，包含 291902 个后半球观测，反向 / antipodal 内点为零；独立 RMS 0.414468100333460 与程序值 0.414468100333448 一致。参考共识覆盖全部 375 张，参考旋转 P95 为 0.339070°、中心 P95 为 0.167528 个相邻相机步长。

室内最终保留 5 个内参组，参考共同 738 张，旋转 median / P95 为 0.035490 / 1.719697°，中心 median / P95 为 0.019101 / 1.784409 steps。此前 `DCIM5072-HDR.jpg` 的 35 个原始验证图像对加权旋转误差为 9.014°，最终为 2.242°。最新运行整体 BA 使用 CUDA，未再出现捕获状态污染引发的 CPU 回退；没有通过人为故障注入验证所有驱动异常。

办公室没有独立真值。与 Global 的共同 899 张中，旋转 median / P95 / max 为 0.075393 / 0.296897 / 4.064312°，此前中间版本最大差异约 11.802°。原异常相机最强图像对误差从 12.326° 降到 4.584°，10 个验证对加权误差从 11.477° 降到 3.917°。改善有原始匹配证据支持，但仍存在几度的尾部差异，不能称为与 Global 完全等精度。

Playroom 的 222 张参考全部进入共识，参考旋转 P95 为 0.211925°、中心 P95 为 0.027549 steps；额外三张仍没有独立参考。四套最终注册姿态均有限，内参组均有效且焦距为正，最大旋转正交误差为 1.65e-14。独立从原始前端读取并检查 9883 条强验证旋转边，未发现符合本轮严重冲突判据（两个不同强邻居、超过 5°、冲突权重至少 80%）的已注册相机。

验收目标是消除明显覆盖丢失、错误内参合并、严重旋转冲突与数值异常，允许 Hierarchical 因局部估计和合并而比 Global 略高的残差。上述四套数据通过本轮验收，但参考并非全部可验证的独立真值，办公室仅有内部与图像对证据，也不能由四套样本推导所有场景均无异常。保留默认容量 2048。

CLI、编辑器、Python 和离线工具构建成功；7 项 SfM / BA / 项目相关 CTest 与 Python 导入测试均通过。实验的版本归档、参数、源码指纹、原始输入校验、资源采样及参考评估在 `experiments/sfm_quality_20261012/`；最终汇总为 `results.json`、`final_verified_conflicts.json`、`guard_pair_audit.json` 与全景 `full_sphere_audit.json`。
