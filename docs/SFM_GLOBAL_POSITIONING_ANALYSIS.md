# 全景数据集全局定位分析（2026-10-13）

后续四组数据集及 Berlin 预算控制结果见 [相机热启动与 CUDA bearing 扩展验证](SFM_BEARING_VALIDATION.md)。

## 结论

375 张全景图默认没有达到 camera_warm_start_min_images=512，因此使用 CPU primary/sparse_schur。降低热启动门槛的实验可以先求解相机中心，再进入 scale-free bearing refinement；在这份数据上，定位结构改进和 CUDA 求解都带来明显收益。

之前拆分并行化 A/B 中，定位从 34.169 s 到 43.606 s 的差值发生在 split 之前，不能归因于 split。原串行记录只有 2 次 IRLS，另两次有 6 次，差值首先来自工作量不同。本次观察到时间预算耗尽时没有有效参数更新，证明预算分配可能导致停滞；旧日志没有每轮 Ceres Summary，无法确定旧串行第 1、2 轮的具体终止原因。

## 方法

- 当前基线提交：7a6e32a；仅增加诊断日志，并让定位 benchmark 支持 PHOTARA_LOG_LEVEL，未改变求解或默认配置。
- 从相同 tracks-6ecf2678d16f436e.bin 检查点读取，顺序运行，实际重新执行 global mapping。
- 375 张图、选中 7500 条轨迹、345201 条定位观测；所有实验最终 BA 都使用 CUDA，拆分均使用已提交的并行实现。
- 默认 CPU 路径复测两次；CPU bearing 热启动与 CUDA bearing 热启动各一次。热启动实验将 benchmark 的 warm_start_min_images 参数从 512 改为 1。
- mapping 耗时包含旋转、轨迹构建、定位、三角化、BA 等；不含图片解码、SIFT、匹配、前端缓存加载、恢复、着色和导出，不能称为冷缓存端到端耗时。
- 日志、命令、二进制/源码/输入哈希、ASFM、参考模型评估及汇总位于 artifacts/sfm_positioning_analysis_20261013/。首次 info 级 CPU 运行作为辅助记录；下表采用两次 debug 级 CPU 诊断运行。

## 性能

| 路径 | 全局定位 | global mapping | 注册数 | RMS |
|---|---:|---:|---:|---:|
| 默认 CPU primary/sparse_schur，两次 | 47.513 / 46.529 s | 55.499 / 54.583 s | 375/375 | 0.369131 / 0.368983 px |
| 相机热启动 + CPU bearing | 16.080 s | 24.510 s | 375/375 | 0.369777 px |
| 相机热启动 + CUDA bearing | 2.872 s | 11.234 s | 375/375 | 0.369777 px |

相对默认路径，CUDA 热启动方案的定位加速约 16 倍，mapping 减少约 79%–80%。相同 bearing 热启动结构下，CUDA 将定位从 16.080 s 降到 2.872 s，因此收益同时来自求解结构与 GPU 执行。CUDA bearing 各轮累计 solve_s 为 0.472480 s，CPU bearing 为 13.5562 s；全局定位还包含相机热启动、构建问题、IRLS 更新与传输。

## CPU 热点和预算问题

默认 CPU 两次分别调用 9 次 Ceres，累计预处理为 14.2395 / 14.3719 s，线性求解为 17.1057 / 16.3476 s。每轮预处理约 1.56–1.65 s，后续单轮预算通常约 2–3 s，导致多轮只接受一个参数更新，却重复执行全部预处理。

第一组最后一轮预算仅 0.432171 s，实际预处理 1.56296 s、总耗时 1.73583 s、accepted_updates=0、initial_cost=final_cost=6.6234，终止原因是 Maximum solver time reached。Ceres 将预处理计入求解预算，并在检查点检查超时，因此预算不是可抢占的严格墙钟上限。全局定位墙钟还包含问题构建和后处理。

代码目前仍在超时无更新后计算 IRLS 权重，且仅根据权重变化量判断 IRLS 收敛。若几何未变化，可能把停滞误当成收敛。诊断新增 accepted_updates 字段，排除 Ceres 仅评估初值的第 0 次迭代；原 num_successful_steps=1 不代表发生了参数更新。

## 质量和适用范围

全部实验注册 375 张，参考模型对齐也有 375 个 inlier。相对默认 CPU，热启动方案 RMS 增加约 0.18%–0.22%；平均旋转误差从 0.1951–0.1954° 到 0.2054°，旋转 P95 从 0.3069–0.3073° 到 0.3123°。中心误差 P95 则从 0.1728–0.1731 个参考步长降到 0.1663，但平均中心误差从约 0.0748–0.0749 增到 0.0782。

CPU bearing 与 CUDA bearing 的轨迹数、观测数和 RMS 在输出精度下相同，参考相机误差接近到约 1e-8；上述相对默认路径的质量变化主要与初始化/目标结构变化相关。没有验证完整输出逐位一致，也没有证明每个质量指标改善。

优先继续实验相机热启动 + CUDA bearing 对 512 张以下、观测足够多的场景的适用性，并验证更多数据和重复运行。当前 GPU bearing 路径还要求至少 50000 条观测、至多 2000 个相机；不能将这一次结果推广到所有场景。同时应改进 CPU 回退路径的短预算处理：记录无有效更新的超时、避免把停滞作为收敛，并评估减少 Ceres 重复预处理。生产默认参数本次保持原值。
