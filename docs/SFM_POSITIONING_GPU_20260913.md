## 后续修复：变量缩放与阻尼

真实办公室 bearing 子问题（896 个有效相机变量、18000 点、421128 观测）被提取为 `office_bearing.bin`，用于绕过前端直接对照 Ceres。第一次单步比较发现相机参数最大差 0.211675；关闭 Ceres Jacobi 缩放后差降到约 9.8e-11，证明主要差异来自缩放后的阻尼下限，而不是 CUDA Schur 的符号或索引。

Ceres 在每次求解开始时以 `s = 1/(1+sqrt(diag(JᵀJ)))` 缩放变量，然后将 LM 对角线夹紧到 `[1e-6, 1e32]`。GPU 使用原参数单位求解时，必须将该上下限乘以 `1/s²`，并在相机阻尼中一起计入基线残差。现已按此处理；缩放在一次内层求解期间固定，在下一轮 IRLS 开始时重新计算。

同时，LM 根据实际成本下降与未加阻尼二次模型预测下降的比值更新信赖域；拒绝步采用逐次增大的阻尼倍数，替代此前无条件固定倍数更新。

真实子问题验证（`scaled_real_step.log`）：CPU/GPU 第 1、8、30 步相机参数最大差分别为 1.07e-10、1.97e-10、2.58e-10，成本一致。合成回归新增单步参数对照及放大 1000 倍坐标的弱方向案例，后者能触发该对角线下限问题。测试程序可接受上述 fixture 路径，并对成本和相机参数差执行失败断言。

完整流程还包含有限迭代 IRLS、三角化和相机恢复，因此子问题通过不代表完整相机质量已经通过。`scaled_gpu.log` 仍出现注册集合变化；增加内层迭代的 `settled_gpu.log` 降至 894 个相机，该尝试已撤回，最终保持原迭代预算。

随后定位到浮点精度问题：虽然投影矩阵在精确算术中满足 `PᵀP=P`，使用简化式以及 `d-u(u·d)` 会在近共线、接近收敛的方向损失相对精度。最终显式形成雅可比并计算 `JᵀJ`、`Jᵀr`，对齐 Ceres 在接受候选步之前进行成本收敛检查的行为。`stable_gpu.log` 中全部 IRLS 轮次的降权/隔离数量与 CPU 一致，最终完整质量通过，见文首。

运行时增加了输入有限值和索引范围验证，以及点块求逆失败检查；不再将失败的点块静默视为零逆矩阵。临时 fixture 导出代码已移除，生产运行不会额外写出定位问题。
