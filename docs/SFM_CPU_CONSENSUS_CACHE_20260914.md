# SfM CPU 三角化效率优化（2026-09-14）

本轮保留默认 GPU 提取、匹配、全局定位和大型 BA 路径，优化这些阶段之间的 CPU 三角化工作。没有减少特征、匹配候选、RANSAC 采样次数、几何检查或重建精度门槛。

固定真实输入的三角化耗时减少约 30%；办公室 900 张图完整冷启动从 309.158 秒降至 288.291 秒，减少 6.75%，注册集合保持 899/900。完整流程仍有少数弱相机的运行间位置变化，详见下方质量边界。

## 实现与等价性

LO-RANSAC 中，不同采样常得到完全相同的初始内点集合。局部优化首先从该集合重建线性系统，覆盖采样点，之后的结果只依赖固定的观测、内点集合与选项。

`triangulation.cpp` 现在在每条轨迹的一次 RANSAC 调用内保存最近一次成功完成的局部优化结果。最多 64 个观测时，内点集合编码为无碰撞的 64 位位集；更长的轨迹不使用该缓存。失败或提前退出的局部优化不进入缓存，因为它可能仍依赖采样点。所有随机数、采样次数、候选比较顺序和相同分数下的选择规则都保留。

内点分类改为复用输出向量；候选与最优解交换缓冲区，减少循环中的分配释放。缓存和缓冲区均在调用内部，不共享跨线程可变状态。

曾尝试并行检查初始分裂候选，输出一致但真实数据耗时未改善（5.738 秒对 5.716 秒），已撤回该尝试。

全局重建耗时减少约 19.0%。前端未在本轮改动，其约三秒差异属于运行波动，不归因于三角化缓存。完整流程是单次应用缓存冷启动比较；GPU 是约 0.5 秒间隔的整卡采样，包含其他应用，不能解释为内核 occupancy 或保证持续满载。CPU 固定输入三轮平均与输出摘要是本次优化的主要受控证据。

未注册图片仍为 `video06_00545.jpeg`。本轮没有降低重定位门槛。`comparison.json` 对全部 899 个共同相机用一次无反射正尺度 Sim(3) 比较：位置变化中位数为旧场景半径的 0.0257%，P95 为 0.0432%，最大 11.60%。不能以全局 RMS 接近宣称所有弱相机位置一致。

独立 CPU SIFT 审查见 `pose_audit.json`。`video03_00391.jpeg` 的 88 条三视角轨迹保持约 0.77 px 中位数、1.97 px P95。部分 `video02` 弱视角仍不稳定，误差有升有降，例如 `00559` 的独立目标误差中位数从 3.39 px 增至 11.00 px。固定输入 CPU 三角化的有序输出摘要完全相同，但不能据此声称整个包含 GPU 优化与恢复的流程逐位确定；本轮不宣称解决了这些弱相机的稳定性。
