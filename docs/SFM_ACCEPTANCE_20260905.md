2026-09-06 的新数据与后续修复见 [SFM_ACCEPTANCE_20260906.md](SFM_ACCEPTANCE_20260906.md)。新一轮以 `ori_img/images` 替换 lego1；本文保留历史证据。

本轮结论：**改进后的默认 SfM 已在 chuan 和 alameda 上通过本轮全部质量门槛，但三组数据仍不足以认证所有产品采集条件。** 修复前，即使全部图片注册且重投影达到亚像素，仍可能出现严重错误的相机轨迹；修复后，chuan 无需人工焦距即可恢复正确轨迹，alameda 的大场景精度和耗时也显著改善。本次保留失败基线、最终运行、标定对照、参考模型一致性审计及可重复执行的验收脚本。

## 环境与评价口径

- Windows，AMD Ryzen 9 7950X（16 核 / 32 线程），约 32 GB RAM，RTX 5090 D v2（24,455 MiB）。Release 构建；SiftGPU + gpu_mutual_ratio，最大 27,000 特征，默认 global、window=3，加 BoW 检索。未执行 MVS 或 splat 训练。
- 原始输入只读：`D:/Models/alameda/images`（1734）、`D:/Models/lego1/images`（300）、`D:/ScanVideo/chuan/images`（109）。输出均在 `artifacts/sfm_acceptance_20260905/`。
- 各自 `sparse/0` 的 COLMAP 模型是独立比较基线，**不是测量真值**。匹配图片名称，用所有公共注册相机拟合一次允许正尺度、禁止反射的 Sim(3)，不删除对齐离群点。
- 位置误差除以公共参考相机中心相对质心的 RMS 半径，再乘 100。旋转使用 world-to-camera 约定，随同 Sim(3) 调整世界坐标。重投影 RMS 按观测数量加权；逐相机 P95 的分布不冒充全部观测的 P95。
- 暂定工程门槛：注册率 ≥98%，参考中可对应输入的相机注册率 ≥98%，重投影 RMS ≤1 px，位置 P95 ≤参考半径的 5%，旋转 P95 ≤3°，每个注册相机至少 30 个有效观测。这是本次筛查标准，并非用户已确认的交付 SLA。
- 墙钟时间、SfM 内部耗时、缓存命中分别记录；不把缓存结果当冷启动结果。性能超时是运行预算，不是产品性能认证。每种配置目前只有一次完整测量，不能提供 P95 延迟或重复性保证。

## 复现并处理的问题

### 1. 大数据集特征提取内存耗尽

原始默认配置在 alameda 的 1651/1734 张附近抛出 `bad allocation`，98.6 秒退出，未产生有效重建。代码在全部图片提取完成后才统一压缩描述子，导致完整浮点描述子集合驻留内存。

修复为每张图完成选择后立即执行原有 uint8 压缩，并每 8 个任务排空一次后处理队列。CPU 提取和 SiftGPU 路径都遵循配置，学习型后端仍遵守原有禁用量化的选择。LightGlue 的 SIFT 检索旁路也立即压缩。

仅应用内存修复的完整冷启动运行 `alameda_memory_fix` 成功完成：1722/1734 注册、1,133,982 点、RMS 0.607 px，SfM 843.4 秒，峰值工作集 7310 MiB。该峰值不是进程提交量或系统总内存。质量仍未通过：位置 P95 8.66%，且存在已注册但有效观测为零的相机。

### 2. 自标定失败后遗漏严格几何过滤

未知内参路径有意保留 F-RANSAC 支持，推迟正深度和严格重投影过滤；原逻辑只在焦距校准成功更新时补做过滤。自标定退化并保留初始焦距时，未过滤的对应会进入 tracks 和 mapping。

现在只要存在未标定内参，就补做相对位姿和严格几何验证；自标定因样本不足或退化而保留先验时输出明确警告，并更新 tracks 缓存指纹。这修复了遗漏分支，**没有解决未知焦距的退化本身**。

### 3. 小规模 BA 的 OpenMP 调度开销

chuan 的初始焦距 844 对照在旧实现中，仅第一阶段 BA 就耗时 150.1 秒，其中求解占 148.2 秒；该对照随后被人工停止并保留超时说明。小规模 PCG 每次点积、预条件和向量更新都反复启动 32 线程。

现在根据向量长度和相机块数量，让小系统执行串行运算，大系统保留并行。未降低优化或 PCG 的迭代上限、精度阈值。不同几何配置的耗时不可直接计算成同问题加速倍数。

修复后 844 可优化初值的完整对照耗时 20.20 秒，第一阶段 BA 0.630 秒（其中求解 0.202 秒），后两阶段 3.956 / 1.845 秒。本轮同时补做了严格几何过滤，所以这是端到端修复验证，不是只修改 OpenMP 的隔离加速比。

### 4. 自动焦距退化导致正确匹配生成错误轨迹

chuan 上原图尺度的初始焦距约 1536 px，原有图优化自标定目标退化后仍保留约 1479 px，造成轨迹折叠。两视图候选焦距受低视差影响整体向低值偏移，但其较高分位仍稳定覆盖合理初值区间。

现在严格几何验证会收集物理范围内的非平面两视图焦距候选；当原有图优化没有给出有效更新时，至少 16 个候选且有足够一致支持才启用对数域 Q75 回退。chuan 最终自动选择 870.4 px（715 个候选），无需参考焦距或新 CLI 参数即通过全部门槛。该回退带有样本数、一致性和物理范围约束，不会用少量退化配对强行覆盖初值。

### 5. 大场景直接点约束初始化慢且易发生布局漂移

alameda 的旧默认路径直接用大量点约束初始化相机，耗时约 742 秒，位置 P95 8.64%。现在注册图像达到 512 张时，先用相对平移约束恢复相机骨架，再继续点约束和 BA；小场景保持原路径，避免改变已有合成测试和 chuan 行为。

最终 alameda 运行的相机预热使用 9579 条相对约束，2.79 秒得到 1722 个初始位姿；完整 SfM 内部耗时 123.0 秒，位置 P95 降至 3.08%，旋转 P95 0.472°。与旧运行的缓存命中层级不同，不能把 747.68/129.06 直接作为严格隔离的加速比，但端到端结果清楚显示新路径同时改善质量和耗时。

### 6. 弱支持相机被计入成功注册

旧 alameda 结果有 24 个注册相机少于 30 个有效观测，其中 21 个为零。现在重建结束前重新检查每个相机的正深度、有限值和 2 px 内重投影观测；支持少于 30 的相机被取消注册，其观测也从轨迹中清理。最终运行剔除 21 个相机，剩余相机最少 32 个有效观测，验收结果不再把无几何支持的位姿当作成功。

### 7. CLI 无法表达已知标定，模式拼写错误会静默走增量路径

新增 `--trust-focal`，显式把正的 `--focal` 作为锁定的外部标定（同时锁定当前零畸变模型）。不能用它表达任意畸变标定。默认 `--focal` 仍只是可调整的初值。

未知 `--mode`、非有限/负焦距，以及没有正焦距的 `--trust-focal` 现在立即失败，不再静默改用另一种模式。负面 CLI 检查已执行。

## 数据质量和剩余问题

chuan 的自动焦距退化已在本数据上修复。锁定 844 和只提供 844 初值的运行仍保留为诊断对照，用于证明原问题来自焦距初值而非匹配或后端选择。新的 Q75 回退是启发式估计，仍需在更多传感器、变焦、混合焦距和低视差数据上验证，不能由单个视频序列推断普适性。

lego1 的 SHA-256 审计确认 300 个文件恰好是 100 个不同图像，每个重复三次。本系统修复后重复相机中心差为零，旋转差只有数值舍入量；但参考中相同文件的相机中心最大相差参考半径的 242.9%，旋转最大相差 177.6°。因此与该参考不一致不能全部归因于本系统。参考只有 275 个注册图像；不能把本系统额外注册的 25 张当成“参考覆盖率失败”。

alameda 的 P95 门槛已经通过，但最大中心误差仍为参考半径的 66.0%，集中在一段弱连接相机序列。P95 会容许少量严重离群，因此产品输出还应暴露逐相机置信度或局部连通性风险，不能只依赖整体通过状态。单凭 `summary.valid`（至少两个注册相机和非零点数）也仍不是产品认证；本轮外部验收脚本提供了更严格的发布门槛。

## 复现

```powershell
python experiments/run_sfm_acceptance.py `
  --exe build/aetherscan/Release/aetherscan.exe `
  --images D:/ScanVideo/chuan/images `
  --reference D:/ScanVideo/chuan/sparse/0 `
  --output-dir artifacts/my-sfm-regression --name chuan `
  --timeout-seconds 300

# 诊断标定对照；实际产品中必须使用该相机自身的可信标定。
python experiments/run_sfm_acceptance.py `
  --exe build/aetherscan/Release/aetherscan.exe `
  --images D:/ScanVideo/chuan/images `
  --reference D:/ScanVideo/chuan/sparse/0 `
  --output-dir artifacts/my-sfm-regression --name chuan-calibrated `

python -m unittest discover -s experiments -p test_sfm_acceptance.py
ctest --test-dir build -C Release --output-on-failure `
  -R 'sfm|features|ba.optimizer|checkpoint|project'
```

runner 为每次运行保存命令、超时/退出码、端到端墙钟、阶段耗时、峰值工作集、缓存命中及质量门槛，并在失败时返回 2。已有名称拒绝覆盖；重跑必须选择新名称。模型、日志和诊断文件在忽略的 artifacts 目录中，不自动提交大文件。

验证：完整 C++ 测试 13/13 通过；Python 验收测试 4/4 通过，覆盖 Sim(3)/旋转约定、二进制模型读取、注册缺失和位姿离群拒收。
