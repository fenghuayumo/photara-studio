# 训练期颜色校正：PPISP 与双边网格（2026-09-14/15）

本报告回答一个问题：把 spirula-studio 的**双边网格颜色校正**和 **PPISP 颜色校正**移植到当前
3DGS 训练后，能否提升重建质量、减少漂浮物。结论先说：**两者都让“去掉拍摄曝光差异后”的重建
明显更好（antman 留出集 +1.4~1.8 dB），但没有提升导出模型本身的留出指标，漂浮物代理指标也
没有一致改善**。因此这两个功能以“可选、默认关闭”的形式交付，并把它们的价值定位在
“拍摄曝光不一致时的训练稳定性与对齐指标”，而不是“导出模型更好看”。

## 为什么要做：拍摄端曝光/白平衡漂移是真实且很大的

逐帧平均亮度（frame mean luminance）统计，直接量出手机视频的自动曝光漂移：

| 数据集 | 帧数 | 亮度均值 | 亮度标准差 | 相对标准差 | 相邻帧一阶自相关 |
|---|---:|---:|---:|---:|---:|
| WeChat_20250712175936 | 198 | 0.5045 | 0.0152 | 3.0% | +0.92 |
| antman_nomask | 64 | 0.3707 | 0.0510 | 13.8% | +0.77 |
| chuan | 109 | 0.4245 | 0.0404 | 9.5% | +0.95 |
| cloth3 | 215 | 0.4744 | 0.0241 | 5.1% | +0.67 |
| stone | 63 | 0.5838 | 0.0243 | 4.2% | +0.63 |
| Gingy | 171 | — | 0.0663 | 13.5% | +0.61 |

室内固定机位以外的数据普遍有 4%~14% 的整帧亮度漂移；自相关高（>0.9）说明是缓慢漂移，
自相关低（<0.8，如 antman、Gingy）说明是逐帧抖动。缓慢漂移可以被 SH 的方向依赖颜色
部分吸收，逐帧抖动不能，只能由几何/颜色去“硬拟合”，这正是重影和丝状残渣的成因之一。

## 实现

移植自 `D:/ProgramCode/C++/spirula-studio`：

- `aetherscan/src/splat/ppisp.cu`：PPISP 光度模型。默认布局 `no_crf_no_vig`（9 参数：
  一个 log2 曝光 + 8 个色彩单应参数，常量矩阵与 spirula-studio 的
  `generated/ppisp.cuh` 完全一致）；另提供 `no_crf`（24 参数，含暗角）与 `original`
  （36 参数，含 CRF）布局。色彩单应的雅可比在设备端用中心差分求，暗角/CRF 的 VJP 同样
  移植。**`channel_gain_bias`（6 参数：三通道 log2 增益 + 三通道偏置）也并入本模块**，
  作为“轻量级”布局，而不是独立代码路径：状态、优化器、正则化只有一套。
- `aetherscan/src/splat/bilateral_grid.cu`：仿射双边网格（每格 3×4 矩阵，12 通道，
  通道后置），在 (x, y, 亮度) 上三线性插值；TV 正则梯度、Adam 更新、identity 初始化与
  reference 的 fused-bilagrid 归一化一致。
- 两个模型都只作用于**训练期**光度损失；导出模型、预览、留出评估始终是 canonical 颜色。

### 两个必需的“锚”约束

第一轮实验里，把每视图变换放开不加约束是**灾难性**的：模型与每视图变换之间存在退化
（场景整体变亮 × 变换整体变暗 等价），优化器会选择一个让 canonical 外观跑偏的解。
第一轮 WeChat 的 canonical 留出 PSNR（30k、split 8、无 mask）：

| 配置 | 有效 PSNR | SSIM | 对齐后 PSNR |
|---|---:|---:|---:|
| 基线（全部关闭） | 35.0886 | 0.9827 | 35.1369 |
| 每视图 gain/bias（无锚） | 30.7618 | 0.9803 | 35.3326 |
| 双边网格（无锚） | 17.0249 | 0.9141 | 29.7150 |
| PPISP（锚过弱） | 32.1119 | 0.9823 | 35.2603 |
| 双边网格 + PPISP | 16.9655 | 0.8946 | 28.6335 |

因此本实现加入两条约束，缺一不可：

1. **PPISP 的均值锚**：把跨视图的曝光均值与色彩均值用 smooth-L1 拉向单位变换。第一版把
   锚梯度乘了 `1/views`，等于让约束强度随数据集规模衰减（198 视图时约弱 200 倍），
   均值仍然漂移；现在锚是“均值的性质”，与视图数无关。
2. **双边网格的均值投影**：每视图网格的自由度数（16×16×8×12）超过该视图的像素数，均值
   不受约束时会吸收全局颜色映射（canonical PSNR 掉 18 dB）。现在每次更新后把每视图、
   每通道的网格均值投影回 identity 仿射，网格只能表达空间变化（镜头阴影/暗角），
   全局曝光与白平衡交给有锚的 PPISP。

## 第二轮（加锚 + 网格均值投影 + 系数边界 + 温和学习率后）

两轮 WeChat（30,000 步，split 8，无 mask，关闭 progressive resolution）。canonical 是导出
模型真实渲染的指标；“对齐后”是逐视图拟合一组增益/偏置后的估计（8 bit PNG，两侧同处理）。

| 配置 | canonical PSNR | SSIM | 对齐后 PSNR |
|---|---:|---:|---:|
| 基线 | 35.0802 | 0.9826 | 35.1373 |
| PPISP `channel_gain_bias` | 31.3689 | 0.9782 | 34.8193 |
| PPISP `no_crf_no_vig` | 32.0799 | 0.9821 | 35.0570 |
| 双边网格（每视图，已加锚） | 26.1393 | 0.9514 | 28.1042 |
| 双边网格（共享一张，边界 ±0.5，lr 2e-4） | 29.7662 | 0.9816 | 30.1843 |
| 双边网格 + PPISP | 26.4536 | 0.9487 | 28.6750 |
| 共享网格 + PPISP | 模型出现非有限值，valid 指标 NaN |

结论：即使加上均值锚、均值投影、系数边界和 10 倍更小的学习率，双边网格仍让 canonical
指标掉 5~9 dB。原因不是发散（训练损失、对齐后指标同样变差），而是**网格与 Gaussian 之间
存在第二重退化**：损失不关心“空间变化的颜色校正”和“Gaussian 自身颜色”谁去解释外观，
优化器把一部分外观放进网格，导出模型（不加网格）就永久丢失这部分颜色。共享网格和每视图
网格都无法在训练期（canonical 导出）语义下修复这一点。网格 + PPISP 组合还会让模型出现
非有限值（valid 指标 NaN），因此**不推荐在训练期使用双边网格**；代码保留，默认关闭。

## antman_nomask 结果（30,000 步，split 8，无 mask，关闭 progressive resolution）

| 配置 | 有效 PSNR | 有效 SSIM | 对齐后 PSNR | 不可见高斯数 / opacity 和 | 近相机高斯数（0.5× / 0.25×） |
|---|---:|---:|---:|---:|---:|
| 基线 | 24.2231 | 0.9560 | 24.8513 | 2070 / 227.4 | 2321 / 286 |
| PPISP `channel_gain_bias` | 23.6255 | 0.9460 | 26.2953 | 1093 / 74.0 | 2510 / 361 |
| PPISP `no_crf_no_vig` | **24.3076** | **0.9595** | **26.6406** | 1751 / 264.0 | 4028 / 1001 |
| 双边网格 | 23.0126 | 0.9505 | 23.8165 | **966 / 87.4** | **1772 / 256** |
| 双边网格 + PPISP | 22.8027 | 0.9524 | 24.3797 | **715 / 43.4** | 1933 / 348 |

“对齐后 PSNR”用保存的渲染图与照片逐视图拟合一组增益/偏置后计算，是“去掉拍摄曝光差异”
的上界估计（8 bit PNG 估计，两侧同样处理）；canonical 指标才是导出模型真实渲染的指标。

要点：

- **对齐后 +1.4~1.8 dB**（PPISP 两种布局）：颜色校正确实把每帧曝光差异从场景拟合里拿掉
  了，重建本身变好。双边网格单独使用时对齐后反而 −1.03 dB：每视图一个 16×16×8 仿射表
  足以拟合该视图这张照片，不迁移到留出视图。
- **WeChat 上 PPISP 反而掉 3 dB**：该数据的曝光漂移是缓慢的（相邻帧自相关 +0.92），原本
  由 SH 的方向依赖颜色承担了一部分“可泛化的曝光补偿”；换成训练期的每视图参数后，这部分
  补偿在留出相机上不再存在，于是 canonical 下降。antman（自相关 +0.77，逐帧抖动）则相反：
  SH 本来就吸收不了抖动，PPISP 让 canonical 持平、对齐后 +1.79 dB。
- **canonical 只有 `no_crf_no_vig` 持平偏正**：+0.0846 dB / +0.0035 SSIM（在文档给出的
  重复性波动量级内）；`channel_gain_bias` −0.60 dB，双边网格 −1.21 dB，两者叠加
  −1.42 dB。留出相机的曝光无法预知，这部分误差不会因为训练期建模而消失，它只在
  “按帧对齐”的评估里体现。
- **漂浮物代理指标与 canonical 指标方向相反**：双边网格把“任何训练视图都不贡献”的高斯
  从 2070（opacity 和 227）降到 966（87），PPISP + 网格降到 715（43）；近相机计数也从
  2321 降到 1772/1933。但代价是 canonical PSNR 下降 1.2~1.4 dB。`no_crf_no_vig` 反之：
  指标不降，但不可见高斯与近相机计数上升。外推（dolly）视图目视对比没有看到背景雾层/
  丝状残渣的一致性减少。

## 结论与默认值

- 两个功能都按 spirula-studio 的数学移植完成，并修掉了“无锚漂移”这个必须修的问题；
- 在测试数据上，PPISP（`no_crf_no_vig`）**提升的是“按帧曝光对齐后”的重建指标
  （+1.79 dB），canonical 指标持平**；双边网格能把漂浮物代理指标降低约一半，但会牺牲
  canonical 指标（−1.2 dB），因此只建议与 PPISP 同时使用，且只在确实需要压漂浮物时用；
- 两者默认关闭，作为可选训练开关保留
  （`--splat-ppisp[=type]`、`--splat-bilateral-grid`，编辑器里也在 Splat 面板暴露）。
- 具体建议：**默认两个都关**。素材若有明显的逐帧曝光抖动（相邻帧自相关 < 0.8，如
  antman / Gingy），可用 `--splat-ppisp --splat-ppisp-type no_crf_no_vig`：它不伤害导出
  模型的 canonical 指标（antman +0.08 dB），并把“按帧对齐”后的指标提升约 1.8 dB。
  双边网格在 WeChat 掉 5.4~8.9 dB、antman 掉 1.2 dB，且与 PPISP 组合时会产出非有限值，
  因此只作为实验开关保留，不建议用于交付。
- 真正能从这些功能受益的场景：需要与照片逐帧对齐的检查/报告、训练稳定性（逐帧抖动会让
  几何去拟合噪声）、以及后续要做“显示端按帧重新对齐曝光”的产品路径。

## 复现

```powershell
python experiments/run_ab.py `
  --dataset D:/ScanVideo/antman_nomask `
  --output artifacts/igs_quality_next_20260914/antman_matrix --camera-audit --visibility-audit `
  --config "baseline:--splat-bilateral-grid=false,--splat-ppisp=false" `
  --config "ppisp_channel:--splat-ppisp=true,--splat-ppisp-type=channel_gain_bias" `
  --config "ppisp_isp:--splat-ppisp=true,--splat-ppisp-type=no_crf_no_vig" `
  --config "bilagrid:--splat-bilateral-grid=true" `
  --config "both:--splat-bilateral-grid=true,--splat-ppisp=true"
python experiments/analyze_matrix.py artifacts/igs_quality_next_20260914/antman_matrix
```

`experiments/igs_camera_audit.py`（近相机）与评估器的 `--visibility-audit`（贡献可见性）
提供漂浮物代理指标；它们都只是诊断，不是漂浮物真值。
